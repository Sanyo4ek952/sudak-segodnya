# Импорт стороннего контента

## Назначение

Импорт — закрытый административный процесс подготовки кандидатов. Сторонний
источник никогда не изменяет публичную ленту напрямую. Публичные организации и
публикации появляются только после явного решения администратора.

## Сквозной flow

1. Администратор проверяет разовый HTTPS URL либо добавляет регулярный источник.
2. Новый регулярный источник сначала сохраняется выключенным и проходит тест.
3. Сервер безопасно загружает документ и выбирает RSS, JSON-LD или версионированный
   доменный адаптер. Неизвестный HTML разрешён только для разовой закрытой проверки;
   регулярный источник с таким обработчиком автоматически не включается.
4. Извлечённые данные нормализуются, снабжаются доказательствами и предупреждениями.
5. Воркер сопоставляет организацию в таком порядке:
   - явная `content_sources.organization_id`;
   - действующая `organizationId`, уже сохранённая в кандидате;
   - единственное точное нормализованное совпадение названия.
6. При надёжном совпадении отсутствующие место и телефон заполняются из организации
   только для тех типов публикации, где эти поля используются.
7. При отсутствии надёжного совпадения создаётся связанный кандидат организации или
   публикация остаётся в закрытой очереди. Приблизительное совпадение не применяется
   без решения администратора.
8. Для уже одобренного материала хранится отдельный `source_version_hash`. Та же
   версия повторно не создаётся; изменённая версия становится кандидатом обновления,
   а явная отмена — кандидатом отмены существующей публикации.
9. Администратор исправляет кандидата и может отдельно сохранить правки. Это не
   создаёт и не меняет публичные данные.
10. Финальные действия: создать черновик, опубликовать/применить обновление,
   подтвердить отмену или отклонить.
11. PostgreSQL RPC атомарно применяет основные данные и фиксирует решение. Изображение
    копируется отдельно; его ошибка сохраняется предупреждением и может быть исправлена
    повторной попыткой.

## Инвариант организации

`publications.organization_id` обязателен. Новость также является новостью
организации и не может быть опубликована без неё. Пока организация не определена,
материал существует только как `content_candidates`.

Для источника одной организации администратор задаёт организацию по умолчанию.
Для агрегаторов поле остаётся пустым, и каждый материал сопоставляется отдельно.

## Состояния источника

- не проверен — источник создан, но успешного теста ещё не было;
- приостановлен — проверен, но регулярный запуск выключен;
- активен — участвует в плановых запусках;
- ошибка — последняя проверка завершилась ошибкой, источник сохраняет диагностику;
- нет обработчика — HTML распознан только общим безопасным разбором; источник
  автоматически приостанавливается и его нельзя включить для регулярного импорта;
- исключён — домен или родительский домен находится в denylist.

Фактическое состояние выводится из `is_active`, `last_tested_at`, `last_error`,
`consecutive_failures` и списка исключённых доменов. Использованный способ разбора
сохраняется как `adapter_id` и `extraction_format` на источнике и каждом запуске.

## Сохранение формы

- «Сохранить правки» обновляет только редактируемый payload кандидата;
- `updated_at` используется для optimistic concurrency: устаревшая форма не
  перезаписывает изменения другого администратора;
- ошибки валидации возвращаются по конкретным полям на русском языке;
- значения формы контролируются клиентским компонентом и не очищаются при ошибке;
- несохранённые изменения предупреждают пользователя при закрытии вкладки;
- расписание редактируется структурированными полями дня и времени, JSON в UI не
  показывается.

## Безопасность

- все таблицы импорта закрыты RLS и доступны только администраторам;
- сборщик использует service role только на сервере;
- финальные решения выполняются через `SECURITY DEFINER` RPC с проверкой
  `auth.uid()` и роли администратора;
- URL ограничены HTTPS, публичными IP, стандартным портом, размером, временем ответа,
  redirect и допустимым content type;
- одобрение требует проверенного доказательства первичного источника;
- действия и изменения payload записываются в `audit_events`;
- административные маршруты и ответы импорта не кешируются для offline-режима.
